## Research plan

The project has two different tasks.

### Task A: construct the target

Use the wording in *Taqrīb al-Tahdhīb* to determine which of Ibn Ḥajar’s original twelve categories applies to the first complete grade-bearing phrase in an entry, following [Rank Target Policy v0.2](RANK_TARGET_POLICY_V0_2.md). An explicitly attributed first grade is included as an operational project assumption; keep the attribution visible and report the target as a proxy, not proven personal agreement. Preserve attached qualifiers and potentially relevant notes in a separate context layer. Detailed affiliation labels such as naṣb and tashayyuʿ are not separate targets, but their wording remains available as context. Build a source-grounded phrase inventory, then use exact-span rules only where the wording and required conditions support them. Human verification remains necessary. This is target construction and preprocessing; Taqrīb-derived text and notes are not model inputs for Task B.

Keep Rank 1, Companion status, visible as its own category and distinguish it from ordinary reliability grades in analysis. Do not add new ranks, merge ranks, or create a replacement taxonomy. If the class distribution cannot support an experiment, report that limitation instead of changing the labels.

### Task B: predict the target from other evidence

The model input is eligible historical evaluative text from other rijāl works and validated narrator relationships. The output is the target constructed in Task A.

**Leakage rule:** *Taqrīb* wording, extracted grade text, and direct or derived encodings of that wording may be used to build labels, but must not appear as Task B features. A model that sees the answer-bearing *Taqrīb* wording is not testing whether other historical evidence can reproduce Ibn Ḥajar’s classification.

## Modelling sequence

1. Manually establish textual boundaries on the pilot before building the rank phrase vocabulary.
2. Build and manually check deterministic target extraction only after the boundary rules are clear.
3. Prepare historical text inputs with source, passage, identity, and attribution evidence.
4. Train a text-only TF-IDF + Linear SVM baseline.
5. Train a graph-only GCN baseline after narrator links and targets are validated.
6. Compare text-plus-graph feature concatenation with the separate baselines.
7. Consider CAMeLBERT-CA or AraBERT only if the amount and quality of labelled data, compute, and baseline results justify it.

These are steps to consider in sequence, not a requirement to implement every model. A transformer is optional. No model is being trained in this phase.
